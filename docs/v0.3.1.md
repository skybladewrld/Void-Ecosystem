# Void Flip v0.3.1 — Depth & Polish

## Purpose

This release adds depth and usability to existing systems rather than adding networking or a fourth game. It preserves schema-v3 progression and every complete v0.3 game.

## Blackglass UX

The logical board is unchanged, but rendering maps the human black side to the bottom. D-pad movement maps through the same perspective. Mandatory captures show a clear `CAPTURE REQUIRED` message, green rings identify legal capturing pieces, and green landing markers appear after selection. The HUD and lower screen show turn, side ownership, pieces, kings, difficulty, mode, and capture state. A concise rules page explains movement, mandatory captures, multi-jumps, promotion, and winning. CPU input is briefly locked while `CPU THINKING...` is visible.

## Voidling redesign

The previous overflowing ten-entry rail is replaced by five reachable tabs: Status, Care, Items, Relics, and Journal. Status combines needs, XP, bond, behavior, thought, equipped relic, and slowly emerging personality traits. Care and item details expose real costs, effects, cooldown/readiness, quantities, and material restrictions.

## Layout and navigation

Reusable pure helpers provide bounded selection windows, scroll indicators, word wrapping, board-perspective mapping, capture-state detection, and Workshop availability. Layered Back navigation stores each page's selected position. Game lists now open a detail page before launching, so Back naturally returns from gameplay to detail to the previous list.

## Module depth

Game details expose mastery, progress, records, challenges, controls, and rewards. Market purchases use a two-press confirmation. Workshop detail shows owned material counts against exact requirements. Codex browsing starts with collection categories and hides unknown entries. Profile remains a sectioned, scrollable local overview. Friends, Trading, and Emulators now explain their actual offline roadmap state without fake controls.

## Device controls

Tab opens global quick settings for volume, simulated brightness, sound, battery, charging, and Node status. H sleeps or wakes the simulator. Sleep pauses active games, blanks the displays, skips normal simulation updates, saves state, and returns to the same module on wake. Brightness and master volume use safe optional schema-v3 fields.

## Validation

The UI was inspected across Home, all five Nyx tabs, Games/detail/gameplay, Market, Workshop, daily/weekly quests, Codex, Profile, Notification Center, Settings, offline roadmap modules, quick settings, and sleep/wake. Logical rendering was also exercised at 0.5x, 1.0x, and 1.5x simulator scales.

## Current limitations

Networking, Node services, online accounts, real trading, emulator launching, community-game execution, Raspberry Pi GPIO, and real battery drivers remain roadmap-only. Brightness is a simulator overlay rather than hardware backlight control. No profile-name editor or mouse/touch input is included yet.
